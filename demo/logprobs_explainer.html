How logprobs work

A from-scratch walkthrough of the measurement + steering idea behind docs/LOGPROBS_RESEARCH_DIRECTION.md. Reference page — interactive, self-contained.

1A model is a next-token probability machine

Given some text, it scores every possible next word. That score, logged, is a logprob.

The capital of France is ___

Probability: how much weight the model puts on that token.

2Turn an opinion into one of these distributions

Force a numbered answer. The first token is "1"–"4" — read the probability on each number.

How much do you trust government to do what is right? Answer 1–4.

That bar chart is the model's stance — captured in a single call. This is what option_logprob_vector() reconstructs in measure.py.

3Why logprobs beat repeated sampling

Old way: ask many times, tally answers (noisy). New way: read the exact probabilities once.

sampled tally (what you'd count) true logprob (read directly)
samples: 0

The grey tally only settles onto the blue truth after ~100 asks. Logprobs give you the blue bars in one call — so the temperature setting stops being what you're accidentally measuring. This is the estimation upgrade in NEXT_EXPERIMENT_DESIGN.md.
